# 规范：JavaScript 和 TypeScript 支持

## 新增需求

### 需求：识别 JavaScript 和 TypeScript 文件
插件**必须**扩展支持的文件类型，以便包括常见的 JavaScript 和 TypeScript 文件扩展名。
#### 场景：识别 JavaScript 和 TypeScript 文件
- **Given** 用户打开了一个扩展名为 `.js`, `.ts`, `.jsx`, `.tsx`, `.mjs`, `.cjs` 的文件
- **When** 插件初始化或监听文件打开事件时
- **Then** 插件应识别该文件为支持的文件类型，并触发翻译扫描和显示逻辑。

### 需求：支持 JSDoc 注释格式
插件**必须**能正确处理和显示 JSDoc 风格的注释翻译。
#### 场景：支持 JSDoc 注释格式
- **Given** 代码中包含 JSDoc 格式的注释（以 `/**` 开头）
- **When** 插件处理该注释的翻译显示时
- **Then** 应正确保留注释格式（如 `/** ... */`），并将翻译内容正确嵌入或替换显示。

### 需求：统一的文件类型判断
插件**必须**提供统一的工具方法来判断文件是否受支持，以减少重复代码并便于维护。
#### 场景：统一的文件类型判断
- **Given** 多个组件（Listener, Annotator, FoldingBuilder, InlayHints）都需要判断文件类型
- **When** 执行文件类型检查时
- **Then** 应使用统一的逻辑或工具类，避免硬编码分散在各处，方便未来扩展。

## 修改需求

### 需求：更新文件后缀检查逻辑
现有的文件类型检查逻辑仅支持 Go 和 Rust，**必须**更新以包含新的 JS/TS 类型。
#### 场景：更新文件后缀检查逻辑
- **Given** 现有的代码中硬编码了 `.endsWith(".go")` 和 `.endsWith(".rs")`
- **When** 应用新的变更时
- **Then** 这些检查应被替换为检查是否属于支持的文件扩展名集合（包括 Go, Rust, JS, TS 等）。
